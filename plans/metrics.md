# Time and tokens per phase

One row per phase, from phase 0. Times are UTC. Each token figure says where it came from:
`measured` is the `subagent_tokens` of an agent's completion notice (not a running total across
resumes: in an earlier project a resumed builder's second notice was lower than its first; whether cached
input counts like fresh input is not known), `estimated` names its source, and
what nobody can read is `unknown`. The builder writes its row before `gh pr ready`; the ready,
merged and released cells cannot be known on the branch, so the next phase's first ship fills
them in from GitHub (see "Time and tokens" in `AGENTS.md`). `End` is the release, or the merge
with "no release" for a branch that feeds nothing into the binary.

The Orchestrator column holds the main session's context at the phase's start and at the end of
its clean review, measured from its transcript (see "Time and tokens" in `AGENTS.md`); its token
use stays `unknown`. Phases 1 to 12 shared one orchestrator session, so their context counts
every phase that ran beside them. Phase 13 was reviewed by a review coordinator, whose final
report carried the reviewers' figures and the builder's fix rounds, its own figure in the Notes
cell. From phase 14 the orchestrator runs Claude Code's `/code-review` itself each round (see
"Review before ready" in `AGENTS.md`): the Claude reviewer cell holds the skill's figures, and
the Codex reviewer cell reads `none`. Rounds and the growth of the orchestrator's context from
start to clean review, before, during and after phase 13, show whether dropping the coordinator
costs context.
